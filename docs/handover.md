# Передача дел · 13 MIRRORS (27.11.2026)

Для человека-разработчика или ИИ-помощника, который подхватывает работу.
Правила владелицы — `CLAUDE.md` (общие для всех помощников) и `AGENTS.md`. Текущее состояние — `docs/status.md`.
Здесь — как всё устроено целиком, на одной странице. Паролей и ключей в этом файле нет и быть не должно.

## 1. Что это
13 MIRRORS — проект психолога: маршруты по 13 дням волн Цолькина, встречи, Карты-Отражения.
Сайт `13mirrors.ru`: главная, **витрина месяца** (`/vitrina/`, сетка 3×3 карточек), страницы маршрутов по дням,
Песочница, «Узнать свой кин», «Узоры», «Пространство», запись на встречи.
Владелица всё содержимое меняет сама в **панели** `13mirrors.ru/vitrina/admin/`; код она не трогает.

## 3. Как изменения попадают на сайт
```
Панель: «Сохранить»    → коммит в 13mirrors-content (черновик, на сайт не идёт)
Панель: «Опубликовать» → один коммит в vitrina/main (только месяцы со статусом «Опубликована»)
Помощник: ветка → она вливает (Compare & pull request → Merge) → main
main любого из двух публичных репозиториев → GitHub Actions «Пересылка на REG.RU» (deploy-regru.yml)
   → FTP+TLS на хостинг REG.RU → 13mirrors.ru (через 2–3 минуты)
```
- Витрина копируется **только** в папку `vitrina/` сайта, главная — в корень (папку `vitrina/` не трогает).
- Пароль FTP — секрет `REGRU_PASSWORD` в Settings → Secrets and variables → Actions **каждого** из двух репозиториев.
  Отдельный FTP-аккаунт видит только папку сайта. На сервере лежит файл-метка `.13mirrors-deploy-root`.
- `deploy-beget.yml` — та же пересылка на запасной хостинг Beget, сейчас только кнопкой (Beget взломан 02.11.2026).
  `check-beget.yml` — проверка копии на Beget, ничего не меняет.
- `CNAME` остался со времён GitHub Pages. Не удалять.
- Если сайт не обновился после «Опубликовать» или влития: GitHub → репозиторий → Actions → «Пересылка на REG.RU»;
  красный крестик — открыть журнал, там написано, что не так.

## 4. Хостинг, домен, серверные программы
- **Домен `13mirrors.ru`** и его DNS — на REG.RU. Поддомены `zapis`, `psypoint`, `host` — A-записи там же.
  Переключение между хостингами — сменой A-записей. ⚠️ В REG.RU не включать «Автоматически настроить DNS»:
  это стирает все записи домена.
- **Хостинг REG.RU** (основной с 12.11.2026), панель ISPmanager, PHP 8.3.
  Сайт `www/13mirrors.ru`; запись — `www/zapis.13mirrors.ru`, корень сайта обязательно `public_html`
  (иначе база `data/zapis.db` доступна из интернета). Сертификат Let's Encrypt продлевается сам.
- **Beget** — запасной хостинг. Взломан 02.11.2026. Её решение: держать вторым вариантом.
  Когда кабинет откроется — сменить там все пароли и ключи.
- **Запись на встречи** `zapis.13mirrors.ru` (`13mirrors-bot/zapis/`): PHP + SQLite, оплата ЮKassa.
  Хранит только занятое время (номер, день, время, вид встречи, статус) — **без имён и контактов**.
  Настройки — в панели, раздел «Запись»; «Состояние» там же проверяет сервер. Пароль записи и ключ ЮKassa —
  в `config.php` на хостинге (не в GitHub). Подробно — `docs/zapis.md`, `13mirrors-bot/zapis/README.md`.
- **Бот ПсиПоинт** `psypoint.13mirrors.ru` (`13mirrors-bot/psypoint/`): тесты и анкеты в Telegram.
  ⚠️ **Хранит ник, id и имя из Telegram и ответы** — тут человек не анонимен (её решение: работа с клиентом).
  После взлома Beget перенос на REG.RU был в плане вторым шагом — проверить, работает ли он сейчас.
- **Бот Host** `@thirteenmirrors_host_bot`: код был одним файлом только на Beget, в GitHub его нет.
  Пока бот не работает, в панели включён переключатель «Бот Host временно не работает — все кнопки ведут в мой Telegram»
  (`settings.contacts.hostOff`). Метки кнопок — `docs/host-labels.md`.

### ⚠️ Анонимность и доступы (её правило)
- Код витрины, главной и `13mirrors-content` можно давать спокойно: данных участников там нет
  (всё личное участника — в его коде и на его устройстве).
- **Доступ к хостингу (REG.RU, Beget) и к базе ПсиПоинта открывает данные её клиентов** (Telegram-ники и ответы анкет).
  Такой доступ — только тому, кому она доверяет, и потом сменить пароли. Помощнику лучше работать с кодом в GitHub
  и проверять локально, а выкладывает на хостинг она сама.

## 5. Код (коротко; подробно — `docs/status.md`, «Как устроено»)
- Чистые HTML/CSS/JS, **ES5**, без сборщиков. Стили с префиксами: `m13-*` у витрины, `a-*` у панели.
- `assets/vitrina.js` + `vitrina.css` — витрина и предпросмотр в панели (`window.M13`).
- `admin/admin.js` + `admin.css` — панель (`window.M13_ADMIN`); вход в GitHub ключом, ключ только в `sessionStorage`.
  Черновик — `localStorage m13-admin-draft-v1` + «Сохранить» (Git Data API, `base_tree` — чужие файлы не стираются).
  «Опубликовать» — `buildSite` → картинки в `media/<sha1>` → один коммит в `vitrina`, пересборка `index.html` месяцев.
- `assets/route.js` + `route.css` — страницы маршрутов (`window.M13R`), `doors.js`, `kaleido.js`, `sun.js`, `storm.js`,
  `uzory.js`, `space.js`, `kin*.js` — сцены и страницы. Номер версии: `window.M13RV` в `routes/*/index.html` и `ROUTE_V` в `admin.js`.
- Данные: `data/settings.json`, `routes.json`, `formats.json`, `showcases/index.json` + `showcases/ГГГГ-ММ.json`,
  `sandbox.json`, `reflection.json`, `events.json`, `journeys.json`.
- Изменили модель данных → в `admin.js` функция `migrate()` догоняет её черновик один раз и только в пустые поля.

## 6. Как проверить у себя
```
mkdir site && cd site
git clone https://github.com/elenarasprugina/vitrina
python3 -m http.server 8000
```
Открыть `http://localhost:8000/vitrina/` и `http://localhost:8000/vitrina/admin/`
(главную — так же, положив рядом `elenarasprugina.github.io` и открыв его папку как корень).
- Любая дата для витрины: `window.M13_TODAY='2026-12-05'` до запуска `vitrina.js`
  (в Playwright — `page.addInitScript`).
- Маршрут: `…/routes/<имя>/?debug=1` — окно «Проверка»: любой день, финал, сброс, пробные коды.
- Проверять на телефоне 390 px и компьютере 1366–1440 px; ей — 1–2 итоговых снимка.

## 8. Чем заменить Claude, если подписки не будет
Формат работы: она пишет словами → помощник меняет код в ветке → она вливает.
- **ChatGPT Codex** (chatgpt.com/codex, входит в платный ChatGPT): ближе всего к этому формату — чат в браузере,
  подключается к GitHub, работает в облаке, делает ветку и pull request. Сам читает `AGENTS.md`.
- **GitHub Copilot** (coding agent): работает прямо в GitHub (задача в Issues или вкладка Agents),
  делает pull request; в платном тарифе можно выбрать модель Claude. Тоже читает `AGENTS.md`.
- Любой помощник начинает с фразы: «Прочитай AGENTS.md и docs/status.md. Задача: …».
